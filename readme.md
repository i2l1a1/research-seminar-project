# LLM Chain (FastAPI + LangChain + OpenRouter)

Этот проект — REST-сервис, который берёт запрос пользователя и прогоняет его через цепочку из трёх LLM: сначала генерация черновика, затем валидация (факты, стиль, безопасность), и в конце — улучшение и структурирование ответа. Всё это делается через единый доступ к моделям OpenRouter, а выбор конкретных моделей на каждый этап управляется конфигом (то есть при желании можно легко поменять).

Эндпоинты:
- `POST /v1/generate` — основной сценарий (запрос —> ответ)
- `GET /health` — проверка работоспособности сервиса

## Почему одной LLM часто недостаточно

У одной модели часть есть компромисс: она может быть либо достаточно смелой (и тогда возрастает риск ошибок и галлюцинаций), либо слишком осторожной (и ответ получается поверхностным). Плюс безопасность и аккуратность формулировок — это не то, что можно гарантировать одним промптом, даже если объяснить LLM все детали.

Поэтому для точных ответов без галлюцинаций я хочу создать цепочку:
- Шаг 1. Даёт быстрый черновик.
- Шаг 2. Выполняет роль валидатора, то есть проверяет факты, соответствие запросу, стиль и безопасность, если где-то есть проблемы — исправляет.
- Шаг 3. Превращает отредактированный материал в нормальный ответ: добавляет детали, делает структуру удобной и логичной.

## User story

Как пользователь, я отправляю текстовый запрос в созданную мой API и получаю:
1. Черновой ответ на свой запрос.
2. Исправления, где модель отмечает проблемы (например, фактические ошибки, стилистические, проблемы с безопасностью) и уточняет формулировки.
3. Финальную версию ответа, которая выглядит цельно и структурировано.
4. Также планируется, чтобы LLM оценивала ответы по критериям.

А если внешняя LLM недоступна или ответ не проходит проверку формата или критериев, сервис корректно обработает ошибку и не сломает клиенту сценарий.

## Основные технологии

- `FastAPI` — REST API
- `LangChain` — оркестрация (этапы 1-3 и обработка ошибок)
- `openrouter.ai` — единый доступ к LLM
- Конфигурация через `ENV` (API ключи и выбор моделей для каждого этапа)
- Контейнеризация: `docker`, `docker-compose`
